# KARIAKOO mobile apps

Three native **Flutter** apps — **Customer**, **Seller**, **Rider** — that talk to the
same Supabase backend as the web app (project `galecacpodrgshzsyitm`). They share one
package, `kariakoo_core` (Supabase client, models, auth, repositories, theme, widgets).

```
mobile/
  melos.yaml                     monorepo task runner
  packages/kariakoo_core/        shared code (depended on by every app)
  apps/kariakoo_customer/        Customer app
  apps/kariakoo_seller/          Seller app
  apps/kariakoo_rider/           Rider app
```

## One-time setup (do this first)

The Dart/Flutter source here is written and ready, but the platform shells
(`android/`, `ios/`) are generated by Flutter, not checked in. After installing Flutter:

1. **Install Flutter + Android Studio**
   - Flutter SDK (bundles Dart): https://docs.flutter.dev/get-started/install/windows — add `flutter\bin` to your PATH.
   - Android Studio (Android SDK + an emulator). Then: `flutter doctor --android-licenses` (accept all).
   - Check: `flutter doctor` — Android section all green.

2. **Generate the platform shells** (run once per app, from `mobile/`):
   ```bash
   flutter create --org tz.co.kariakoo --project-name kariakoo_customer --platforms=android,ios apps/kariakoo_customer
   flutter create --org tz.co.kariakoo --project-name kariakoo_seller   --platforms=android,ios apps/kariakoo_seller
   flutter create --org tz.co.kariakoo --project-name kariakoo_rider    --platforms=android,ios apps/kariakoo_rider
   ```
   `flutter create` on an existing folder keeps our `lib/` and `pubspec.yaml` and only
   adds the missing `android/`, `ios/`, etc. (If it ever asks to overwrite `lib/main.dart`,
   say no / restore it from git.)

3. **Get dependencies**
   ```bash
   dart pub global activate melos
   cd mobile && melos bootstrap        # runs `flutter pub get` in every package
   ```
   (Or run `flutter pub get` inside each app and the core package.)

## Running an app

Pass the Supabase keys at run time (the publishable key is the same client-safe value
as the web app's `NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY`):

```bash
cd apps/kariakoo_customer
flutter run \
  --dart-define=SUPABASE_URL=https://galecacpodrgshzsyitm.supabase.co \
  --dart-define=SUPABASE_KEY=<your sb_publishable_... key>
```

For native Google sign-in, use the convenience launcher after setting the values in
`mobile/.env.local` (already git-ignored) or your local shell. Never put credentials
in tracked files. The launcher loads the ignored file automatically and passes the
values only as `--dart-define` arguments:

```powershell
$env:SUPABASE_KEY = 'sb_publishable_...'
$env:GOOGLE_SERVER_CLIENT_ID = '...apps.googleusercontent.com'
$env:GOOGLE_IOS_CLIENT_ID_CUSTOMER = '...apps.googleusercontent.com' # choose matching app
.\run.ps1 customer # or seller / rider
```

For iOS, set `GOOGLE_IOS_CLIENT_ID_CUSTOMER`, `GOOGLE_IOS_CLIENT_ID_SELLER`, or
`GOOGLE_IOS_CLIENT_ID_RIDER` for the app you are launching. The scripts accept the
generic `GOOGLE_IOS_CLIENT_ID` as a fallback.

On macOS/Linux, export the same three variables and run `./run.sh customer` (or
`seller` / `rider`). The scripts pass values only as `--dart-define` arguments.

## Rider app — location permission

The rider app uses real device GPS (`geolocator`) to go online. After `flutter create`
generates its `android/`/`ios/` shells, add the permissions once:

- `apps/kariakoo_rider/android/app/src/main/AndroidManifest.xml` (inside `<manifest>`):
  ```xml
  <uses-permission android:name="android.permission.ACCESS_FINE_LOCATION"/>
  <uses-permission android:name="android.permission.ACCESS_COARSE_LOCATION"/>
  ```
- `apps/kariakoo_rider/ios/Runner/Info.plist`:
  ```xml
  <key>NSLocationWhenInUseUsageDescription</key>
  <string>KARIAKOO uses your location to send you nearby delivery jobs.</string>
  ```

## Sign up with Google (customer / seller / rider)

All three apps share one sign-in screen (`kariakoo_core` → `AuthScreen`). Besides
email + password, it shows **Continue with Google** once the Google client ID is
supplied (admin has no mobile app, so it never gets Google). First Google sign-in
creates the Supabase account and grants the `customer` role, exactly like an email
sign-up; sellers and riders then apply for their role in-app.

The code is already wired (`AuthRepository.signInWithGoogle`, `google_sign_in`
package). To switch it on:

1. **Create Google OAuth clients.** In [Google Cloud Console](https://console.cloud.google.com/):
   - Select the KARIAKOO Google Cloud project from the project picker, or create one.
     Open **Google Auth Platform > Branding**, set an app name and support email,
     then open **Audience**, choose **External**, and add your test account under
     **Test users** while the consent screen is in testing.
   - Open **Google Auth Platform > Clients > Create client > Web application**.
     Name it `KARIAKOO Supabase`. Under **Authorized redirect URIs**, add the callback
     shown at Supabase **Authentication > URL Configuration**:
     `https://galecacpodrgshzsyitm.supabase.co/auth/v1/callback`. Click **Create**
     and record the Web **Client ID** and **Client secret**.
   - Create three **Android** clients, one per app. Enter package names
     `com.kariakoo.customer`, `com.kariakoo.seller`, and `com.kariakoo.rider`, and
     the debug signing SHA-1 for this Windows machine:
     `09:50:2D:A6:7E:BB:AE:29:93:0B:05:60:C0:42:AA:BE:CE:92:6F:9E`.
     To re-check after changing the debug keystore, run
     `cd android; .\gradlew signingReport` on Windows (or
     `cd android && ./gradlew signingReport` on macOS/Linux) and copy `SHA1` from
     `Variant: debug`.
   - Create three **iOS** clients, one per app, with bundle IDs
     `com.kariakoo.customer`, `com.kariakoo.seller`, and `com.kariakoo.rider`.
     Record each iOS **Client ID** for the app's URL scheme and run configuration.
   - Created IDs: Web `966761629099-tfuvmihotlbnrl9rv54vv4t63blb805r.apps.googleusercontent.com`;
     customer iOS `966761629099-gctthm9jiqs13uen72opug1e5blmffh1.apps.googleusercontent.com`;
     seller iOS `966761629099-8ipg37rlrtjg5vgsi8gdpp729mjsanjk.apps.googleusercontent.com`;
     rider iOS `966761629099-k5f072ootlt6mld50a45328v2c99t2pj.apps.googleusercontent.com`.
     Android clients still need their debug SHA-1 fingerprints.
2. In the [KARIAKOO Supabase dashboard](https://supabase.com/dashboard/project/galecacpodrgshzsyitm/auth/providers),
   enable **Authentication > Providers > Google**, set its Web Client ID and secret,
   and add all three iOS plus all three Android client IDs under **Authorized Client
   IDs**. Keep **Confirm email** off if new accounts should be signed in immediately.
3. **Immediate sign-up is enabled for testing.** Supabase **Authentication > Providers** currently has **Confirm email** off, so a new account can receive a session directly.
4. **iOS URL schemes are configured.** Each app Info.plist contains the reversed
   scheme for its iOS OAuth client. Android needs no extra manifest entry for Google
   sign-in; Google matches the Android client by package and SHA-1.
5. **Run with the client IDs.** Set `SUPABASE_KEY` to the project's
   `sb_publishable_...` key, `GOOGLE_SERVER_CLIENT_ID` to the Web Client ID, and on
   iOS set the app-specific `GOOGLE_IOS_CLIENT_ID_CUSTOMER`, `_SELLER`, or `_RIDER`
   to the matching iOS Client ID. Use `mobile/run.ps1` or `mobile/run.sh` as shown
   above. The Google button appears when the Web Client ID is set.
## Notes

- **Security** is enforced by Supabase Row Level Security (same as the web app). The apps
  only ever use the **publishable** key — never a service/secret key.
- **Email confirmation is OFF** in Supabase for immediate sign-up during testing.
- Maps use free OpenStreetMap/MapLibre tiles (`flutter_map`) — no paid Google Maps key.
